## 📖 学习内容（约 25 分钟）

### 1. 词向量 vs 句向量（word vs sentence embedding）

最早的 embedding 是**词向量（word vector）**：一个词 → 一个固定向量。它的灵魂是那个被引爆全行业的类比——`king - man + woman ≈ queen`，第一次证明"语义可以做加减法"。但词向量有两个工程死穴：① **一词一向量、无上下文**——"苹果"在"吃苹果"和"苹果发布会"里是同一个向量，分不开；② 句子要先拆词再平均，长句信息被摊平。

**句向量（sentence embedding）**直接把整句 → 一个向量，上下文已编码进去，这才是今天 RAG/检索能用的形态。一句话区分：

| | 词向量 word2vec/GloVe | 句向量 nomic/bge/E5 |
|---|---|---|
| 输入粒度 | 一个词 | 整句/整段 |
| 上下文 | 无（静态） | 有（同句不同义可分） |
| 用途 | 词类比、特征 | 语义检索、聚类、去重 |
| 类比 | 字典里每个字一个坐标 | 整句话编译成一个坐标 |

今天用的 `nomic-embed-text` 就是句向量模型，输出 **768 维**——可以理解为给每句话发一个"768 维的身份证号"。

### 2. 嵌入模型原理（how embedding models work）

嵌入模型本质是一个**只取编码器、砍掉生成头的 Transformer**：句子进去过 12 层注意力，得到每个 token 的向量，再**池化（pooling，通常 mean-pooling 取平均）**成一个定长向量。后端类比：和你把一个对象 `hash` 成定长摘要一样——但这是"语义 hash"，相似输入产出相邻输出（普通 hash 恰恰相反，要求雪崩）。

它怎么学会"意思近就靠近"的？靠**对比学习（contrastive learning）**：训练时喂大量"正样本对"（同义/问答对）拉近、"负样本"推远。跑几千万对之后，模型就把整个语言塞进了一个 768 维空间，方向 = 语义。维度只是容量：768 维够日常，越高越细但越贵。

### 3. 余弦相似度（cosine similarity）= 比"方向"不比"长短"

两个向量多像，**只看夹角不看模长**：`cos = (A·B)/(|A|·|B|)`，落在 [-1,1]，1=同向(最像)、0=无关、-1=相反。为什么不用欧氏距离？因为"the cat" 和 "cat" 的向量长度可能差很多，但方向几乎一致——我们只在乎语义方向。工程上常先 **L2 归一化（把模长缩成1）**，之后点积就直接等于余弦，一行就够：

```python
def cos(a,b): d=sum(x*y for x,y in zip(a,b)); return d/(math.sqrt(sum(x*x for x in a))*math.sqrt(sum(y*y for y in b)))
```

检索就是：query 嵌成向量 → 和库里每条算余弦 → `sorted(reverse=True)` 取 Top-K。这就是向量数据库内核的 1% 概念精髓。

### 4. 语义检索的本质（what semantic search really is）

关键词检索是字符串匹配："数据库"搜不到"DB"。语义检索是**坐标距离**："如何让接口更快"能命中"优化 API 延迟"——零字面重叠，但向量相邻。本质：把"找相似文本"从字符串问题变成几何问题。RAG 第一步就是它：离线把文档切块嵌入存库，查询时嵌 query 取 Top-K 喂给模型。后端记三件事：**向量定长（可建索引）、相似=ORDER BY 余弦、近义≠近字面**——其余都是 HNSW/IVF 这些索引加速 ORDER BY 而已。
