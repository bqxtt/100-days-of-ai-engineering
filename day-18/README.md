## 📖 学习内容（约 30 分钟）

### 1. Prompt 即代码，必须版本化（核心心智）

后端不会把数据库密码硬编码进函数，也不会改 SQL 不留 commit。Prompt 一样：**它是会直接决定线上效果的关键资产**，却最容易被人随手改、改坏了没人知道、想回滚找不到旧版。把它当代码：

```
手写时代：  prompt = "把工单分类：" + text          # 散落各处，改了不可追溯
工程化：    模板入册 -> 带 version + 指纹 -> 评估通过才上线 -> 可回滚
```

为什么要**内容指纹**（fingerprint）：正文改一个字，sha256 就变。它让你回答三个工程问题——这版和上版是不是同一份（A/B 才公平）、缓存键变没变（呼应 Day13 提示缓存）、线上跑的到底是哪版。版本号 + 指纹 = prompt 的"git commit"。

### 2. 模板引擎：变量插值 + 版本号

模板正文里留占位符 `{{text}}`，运行时插入变量。这和后端的 Jinja2/字符串模板同构，关键是**模板与数据分离**：模板入册可复用、可比对，数据每次请求才填。

```python
body = "仅从[退款,物流,投诉]里选一个。工单：{{text}}"
t = PromptTemplate("classify", version=2, body=body)
t.render(text="我要退钱")   # -> "...工单：我要退钱"
```

守则：① 缺变量要报错，别让带洞的 prompt 上线；② 同名 prompt 多版本存一处（注册表），`latest()` 取最新、`get(name,v)` 回滚到旧版；③ 模板正文里别拼时间戳/随机串，否则指纹天天变、缓存全失效。

### 3. A/B 测试：两版对跑，用数据选

新写一版 prompt 觉得更好？**别凭感觉**——让 v1、v2 跑同一批用例，比准确率。准确率高的灰度上线，另一版进回滚池。三个要点：

- **同分母**：两版必须跑**完全一样**的用例集，否则比的是题不是 prompt。
- **小步快跑**：先小批离线对比，赢了再小流量灰度，最后全量。
- **可回滚**：v2 上线发现回归，一行切回 v1，因为旧版还在册。

### 4. 离线评估指标：分数从哪来

评估的核心是"一个能给 prompt 输出打分的函数"。分数三来源：① **规则/精确匹配**（分类准确率、是否合 schema，最便宜最稳，今天先用它统计两版命中率）；② **LLM-as-judge**（让模型当裁判按 rubric 打分，今天 practice 用本地 qwen2.5 真跑这步，覆盖开放式任务）；③ **人工标注**（最准最贵，做金标准）。常用指标：accuracy、pass@k、cost/latency、合规率。工程上：**先离线评估卡门槛，过线才进线上 A/B**，省钱省事故。
