## 📖 学习内容（约 25 分钟）

### 1. Encoder block = 一条标准化的处理流水线

一个 Transformer Encoder block 把一组 token 向量「进货 → 加工 → 出货」，输入输出形状完全一样（都是 `[序列长度, d_model]`），所以可以像中间件一样叠 N 层。每一层做两件大事，每件后面跟一个「兜底机制」：

```
x  →  [Multi-Head Attention]  → +x（残差） → LayerNorm  →  [FFN]  → +x（残差） → LayerNorm  →  out
        让 token 互相看一眼            原稿不丢      对齐量纲      逐位置加工      原稿不丢      对齐量纲
```

四个组件，逐个对应后端直觉：

| 组件 | 公式直觉 | 工程类比 |
|---|---|---|
| **Multi-Head Attention** | 每个 token 按相关性加权聚合全句信息 | 一次 N×N 的「广播 + 投票」检索 |
| **FFN（前馈网络）** | `max(0, xW1+b1)W2+b2`，逐 token 升维再降维 | 对每条记录独立做一次重计算（无状态、可并行） |
| **残差连接 Residual** | `out = x + f(x)` | 不替换、只追加 diff——梯度有条直达高速路，深层不会失忆 |
| **层归一化 LayerNorm** | 把每个向量拉到均值 0 方差 1 | 每层入口先「标准化数据格式」，数值不爆炸 |

记住公式骨架：`x' = LN(x + Attn(x))`，再 `out = LN(x' + FFN(x'))`。残差是把「原稿 x」加回来，LayerNorm 是把和拉回标准刻度。FFN 维度通常放大 4 倍（512→2048→512），是参数量大头。

### 2. 为什么要「多头」（Multi-Head）：一次检索看不全

单头注意力只产出**一套**权重，全句被迫用同一个视角对齐。多头把 `d_model` 切成 h 份，**并行跑 h 套独立的 Q/K/V**，每头学不同关系（一头管语法、一头管指代、一头管远距离依赖），最后拼接再投影：

```
省钱关键：总维度不变。512 不是做 8 次 512，而是切成 8×64，各管 64 维 → 算量≈单头，视角×8
MultiHead = Concat(head₁…head_h) · Wᴼ，   head_i = Attention(QWᵢ, KWᵢ, VWᵢ)
```

类比后端：与其用一个超长 SQL 把所有逻辑塞进去，不如开 8 个小查询并行各看一面，结果汇总——又快又全。

### 3. 正弦位置编码：给「无序」注意力补上语序

Attention 本身**没有顺序概念**（打乱 token 结果一样，是个集合操作）。位置编码（Positional Encoding）给每个位置加一段「指纹」补回顺序。用一组不同频率的 sin/cos：

```
PE(pos,2i)=sin(pos/10000^(2i/d))   PE(pos,2i+1)=cos(pos/10000^(2i/d))
```

直觉=**多位二进制时钟**：低维快变（个位），高维慢变（高位），合起来唯一编码每个位置，且相邻位置编码接近、相对距离可由三角恒等式线性表示——所以能外推到训练时没见过的长度。今天可视化里你会亲眼看到那张经典斑马纹热力图。
