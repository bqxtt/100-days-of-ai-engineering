## 📖 学习内容（约 25 分钟）

### 1. RAG 总览：检索 + 生成，本质是两套系统拼起来

RAG（Retrieval-Augmented Generation，检索增强生成）解决一个痛点：大模型不知道你公司的私有知识，硬问就**幻觉**。思路朴素到像后端：**先查库，再让模型照着查到的内容作答**。

```
                ┌── 索引侧 (indexing，离线，写库) ──┐   ← 今天 Day27
   文档 → 分块 → 嵌入 → 向量库
                └────────────────────────────────┘
                ┌── 问答侧 (query，在线，读库) ────┐    ← 明天 Day28
   问题 → 嵌入 → 检索Top-k → 拼进Prompt → 大模型作答
                └────────────────────────────────┘
```

类比后端再熟悉不过：**索引侧 = 建索引（写时一次，离线批处理）**，**问答侧 = 查索引（读时高频，在线低延迟）**。RAG = 检索系统(Retrieval) + 生成系统(Generation)，今天只碰前半。

### 2. 索引侧四步流程（今天全部手搓一遍）

| 步骤 | 英文 | 干啥 | 后端类比 |
|---|---|---|---|
| 加载 | load | 把 PDF/网页/MD 读成纯文本 | ETL 的 Extract |
| 分块 | chunk | 长文切成 200-500 字小片+重叠 | 大文件分片入队 |
| 嵌入 | embed | 每片 → 一个 768 维向量 | 给每行数据算 hash/特征 |
| 入库 | index | 向量 + 原文存进向量库 | 写倒排索引/ANN 索引 |

**关键直觉**：嵌入(embedding) 把"语义"压成数字坐标，意思相近的文本坐标也相近（Day21 已学）。今天用 **nomic-embed-text** —— 开源、本地、768 维、免费。一条铁律：**建库和查询必须用同一个嵌入模型同一维度**，否则坐标系都不一样，检索全乱。

### 3. 分块为什么重要（块太大太小都翻车）

- 块太大：一个块塞太多主题，向量被"平均"成糊，检索不准；还吃 token。
- 块太小：句子被切断，丢上下文，模型看不懂。
- 实践：200-500 字 + 重叠(overlap) 几十字，避免在关键句中间切开。Day23-24 专门讲分块策略，今天先体会"切了才好查"。

### 4. 入库 = 向量 + 原文。最小可用版就是一个 numpy 矩阵

不用先上 Chroma/Milvus。把 N 个块嵌成 `(N, 768)` 矩阵，**行归一化**后，检索就是 `M @ q` 一次矩阵乘——点积即余弦相似度，最快暴力法。理解了这个，向量库只是把它做大做快做持久，原理不变。这就是今天给明天问答铺的"地基"。
