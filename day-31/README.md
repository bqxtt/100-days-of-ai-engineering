# Day 31 — Multi-hop RAG：多跳推理、知识图谱增强

> **阶段**：Phase 3 · RAG 系统设计与实现
> **主题**：单跳 vs 多跳（single-hop vs multi-hop）、问题分解（query decomposition）、迭代检索（iterative retrieval）、知识图谱增强（GraphRAG）的直觉
> **预计耗时**：约 1 小时
> **给后端工程师的一句话**：前几天你的 RAG 是「查一次资料 → 答」——可面对「A 公司 CEO 的母校在哪座城市？」这种问题，一次检索永远凑不齐答案：你得先查到 CEO 是谁，再拿这个人名去查母校，再拿母校去查城市。这就是 **multi-hop**：把大问题拆成几跳子问，**每跳检索的输入依赖上一跳的输出**——本质就是你天天写的「分页接力 / 多服务串调」，只不过中间环节换成了「向量检索 + 模型」。今天用本地 nomic 嵌入 + qwen2.5:3b 真跑一个 2 跳。

双击打开 `visualize.html`（纯浏览器，零依赖，深色，纯 canvas）。它把一次 2 跳检索的链路画给你看：① 复合问题进来 → 被拆成「子问 1、子问 2」；② **Hop 1** 子问 1 去文档库里检索、命中片段、模型抽出中间答（如「Acme 的 CEO = 林韵」）；③ 这个中间答**回填**进子问 2 → **Hop 2** 拿新子问再检索、命中、得最终答；④ 末尾把两跳证据合成最终回答。看完你就懂 multi-hop 的「形状」：**一条有向链，后一跳吃前一跳的果**。先玩后读最直观。

## 📖 学习内容（约 30 分钟）

### 1. 单跳 vs 多跳：一次检索为什么不够

**单跳 RAG（single-hop）**：问题 → 检索 top-k → 塞进上下文 → 答。Day 21-30 的做法。对「Acme 是谁创立的？」够用，因为答案就摊在某一段里。

**多跳问题（multi-hop QA）**：答案不在任何单段，要把多段**串起来推**。经典例子：「Acme 公司 CEO 的母校位于哪座城市？」——没有哪段同时写齐「CEO 是谁」+「他读哪所大学」+「那大学在哪」。一次检索按整句去匹配，只会捞回一堆相关但拼不出答案的片段。

| | 单跳 single-hop | 多跳 multi-hop |
|---|---|---|
| 检索次数 | 1 | 2~N（逐跳） |
| 跳间依赖 | 无 | 后一跳输入 = 前一跳答案 |
| 后端类比 | 一次 SELECT | 多次串调，靠上次结果带参 |
| 失败模式 | 漏召回 | 中间跳错，错误层层放大 |

记住一句：**多跳 = 检索-推理-再检索的循环**，跳数 = 推理深度。

### 2. 问题分解（query decomposition）：让模型先拆题

多跳第一步不是检索，是**拆**。把复合问题交给 qwen2.5:3b，让它列出「要回答总问，得先依次查清哪几个子问」：

```
复合问：Acme 的 CEO 母校在哪座城市？
拆解：  子问1: Acme 的 CEO 是谁？
        子问2: <子问1答案> 的母校是哪所大学？   ← 占位符，等回填
        子问3: <子问2答案> 在哪座城市？
```

子问里带占位符，**串行**执行：上一跳答出来才能把下一跳问题填全。这和 ReAct 的「想一步→做一步」同源，只是「做」固定成了「检索」。

### 3. 迭代检索（iterative retrieval）：逐跳 nomic 检索 + 回答

每一跳是一个小单跳 RAG：① nomic-embed-text 把子问嵌成向量 → ② 和文档库余弦相似度取 top-k → ③ qwen2.5:3b 只看这几段，抽出该跳答案 → ④ 答案回填进下一跳子问。如此接力到末跳，再把全部证据合成最终答。模型嵌入/生成分工不变（嵌入只懂相似度、生成才懂推理），变的是**外面套了个循环**。

### 4. 知识图谱增强（GraphRAG）直觉：把跳变成走边

逐跳检索靠「文本相似」连点，可能跳偏。**GraphRAG**（微软）换思路：先把文档抽成**知识图谱**（实体作点、关系作边，如 `林韵 —CEO— Acme`、`林韵 —母校— 清华`），多跳就是**沿边走图**——「CEO 母校城市」= 沿 CEO→母校→所在城市 三条边走到底，确定性强、可解释，还能社区摘要做全局问答。代价是建图贵。直觉：**向量检索按相似找，图检索按关系走**；难多跳两者常合用。

## 🔗 推荐资源（约 15 分钟，按兴趣选）

1. **HotpotQA（多跳 QA 基准与论文）** — https://hotpotqa.github.io/ —— 多跳数据集鼻祖，看几道样题就懂「为什么必须跳两次」。
2. **GraphRAG（微软官方仓库）** — https://github.com/microsoft/graphrag —— 知识图谱增强 RAG 的工程实现 + 论文链接，对照第 4 节直觉。
3. **IRCoT：交错检索与思维链** — https://arxiv.org/abs/2212.10509 —— iterative retrieval 的代表论文，「检索一步、推理一步」交替到答出来。
4. **LangChain Multi-query / decomposition 文档** — https://python.langchain.com/docs/how_to/multiple_queries/ —— 问题分解在框架里怎么落地。
