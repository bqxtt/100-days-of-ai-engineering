> **阶段**：Phase 1 · 大模型核心原理
> **主题**：自回归推理为何慢、KV Cache（缓存历史 K/V）、显存代价、Speculative Decoding、batch 与吞吐
> **预计耗时**：约 1 小时
> **给后端工程师的一句话**：今天学的全是你最熟的活——**缓存（cache）**。大模型每生成一个字都要把前面所有字重算一遍，慢得离谱。KV Cache 就是把算过的中间结果存下来不重算，跟你用 Redis 给热点接口加缓存一模一样。理解这个，你就理解了「为什么推理 GPU 显存这么贵」。

## 📖 学习内容（约 25 分钟）

### 1. 自回归推理（Autoregressive Inference）为什么慢

大模型生成文本是**一个字一个字（token by token）吐**的：先有 prompt，预测下一个 token，把它拼回去，再预测下一个……这叫**自回归**。问题在于：每生成一个新 token，Transformer 的注意力（Attention）都要让它去「看」前面**所有** token。

注意力的核心是三个矩阵：**Q（Query 查询）、K（Key 键）、V（Value 值）**。

```
朴素做法：生成第 n 个 token 时，把前面 n 个 token 全部重新过一遍网络，重新算 Q/K/V
          序列每长 1，重算量就多一截 -> 总计算量 ∝ n²  （二次方爆炸）
```

后端类比：这就像每来一个请求，你不查缓存，把整张数据库表**从头全表扫描**一遍。能不慢吗？

### 2. KV Cache：缓存历史 K/V，省掉重算

关键洞察：**已经生成的 token，它们的 K 和 V 永远不会变**。第 5 个 token 的 K/V，等到生成第 100 个 token 时还是同一个值。既然不变，为什么每步都重算？**存下来（cache）就行。**

```
有 KV Cache：生成第 n 个 token 时
  只为「新来的这 1 个 token」算 Q/K/V
  K/V 追加进 cache（append），Q 去和 cache 里全部 K/V 做注意力
  总计算量从 ∝ n² 降到 ∝ n   （每步只算 1 个，不重算历史）
```

| 对比项 | 无 KV Cache（重算） | 有 KV Cache（缓存） |
|---|---|---|
| 每步新算的 token | 全部 n 个 | 只 1 个 |
| 总计算量 | ∝ n²（二次方） | ∝ n（线性） |
| 后端类比 | 每次全表扫描 | 热点结果进 Redis |
| 代价 | 算力炸 | 吃显存（cache 越长越大） |

这正是 Day 1 思考题埋的伏笔：前向算出来的中间结果（K/V）存下来重用——一存就停不下来，于是显存就成了瓶颈。

### 3. 显存代价：天下没有免费的缓存

KV Cache 把「算力」换成了「显存」。缓存大小随**上下文长度线性增长**，公式直觉：

```
KV Cache 显存 ≈ 2(K和V) × 层数 × 序列长度 × 注意力维度 × batch × 精度字节数
```

跑长上下文（几万 token）时，KV Cache 能占掉几十 GB 显存，比模型权重本身还大。所以推理框架最头疼的就是 cache 管理——和你管线上连接池、内存池一个性质：**省 CPU 但烧内存，必须精打细算回收**。vLLM 的 **PagedAttention** 就是把这套缓存按「内存分页」管理，像 OS 管虚拟内存一样减少碎片。

### 4. Speculative Decoding：小模型猜、大模型验

自回归是串行的——大模型一步只出一个 token，GPU 大量时间在等。**投机解码（Speculative Decoding）**让一个**小模型（draft）**先快速猜出未来几个 token，再让**大模型（target）一次性并行验证**：猜对的全留下，第一个猜错的丢弃重来。

```
小模型连猜 4 个 -> 大模型一次并行验 4 个 -> 对的 3 个全收，省 3 步
不损失质量（验证机制保证输出和大模型单独跑完全一致），只赚速度
```

后端类比：**乐观锁/预取**——先乐观地批量预测，事后校验，冲突才回滚。再加上 **batch（把多请求拼一起喂 GPU）** 提吞吐，就是工业级推理优化的两板斧：KV Cache 砍重算、speculative 砍串行、batch 喂满 GPU。

1. KV Cache 把计算量从 n² 降到 n，代价是显存随长度线性涨。这和你给接口加 Redis 缓存的「省 CPU、烧内存」权衡像不像？什么时候缓存反而不划算？
2. Speculative Decoding 为什么能保证「不掉质量」？验证机制做了什么，让结果和大模型单独跑完全一致？
3. batch 越大吞吐越高，但单请求延迟和显存也涨——这和你调线程池/批处理大小的权衡是不是一回事？哪个场景该牺牲延迟换吞吐？
