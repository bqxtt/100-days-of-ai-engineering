# Day 2 — 词嵌入与语言建模：从 Word2Vec 到语言模型的概率视角

> **阶段**：Phase 1 · 大模型核心原理
> **主题**：词向量、Word2Vec、余弦相似度、语言模型=预测下一个词的概率
> **预计耗时**：约 1 小时
> **给后端工程师的一句话**：模型读不懂"国王"两个字，只认数字。词嵌入（Embedding）就是把每个词压成一串浮点数（一个向量），让"语义近"= "向量近"。今天你会亲手验证「国王 - 男人 + 女人 ≈ 女王」，并理解语言模型不过是在做一个超大号的多分类——猜下一个词。

## 📖 学习内容（约 25 分钟）

### 1. 词向量是什么：把词变成坐标

模型只会做矩阵乘法，不认识字。所以第一步永远是**把词编号成数字**。但光编号不够，得让数字带上"语义"。词嵌入就是给每个词一个固定长度的向量（如 300 维），方向相近 = 意思相近。

```
后端类比：你用 user_id 标识用户，但 id=1001 和 id=1002 之间没有"距离"含义。
词向量：   "猫"=[0.2,-0.7,...]  "狗"=[0.3,-0.6,...] —— 数值上就挨着，因为都是宠物。
```

记住：**Embedding 是一张可查表**。词表里 5 万个词，每个映射成 1 个 300 维向量，就是一个 50000×300 的矩阵。给词 ID，查一行，得到向量。这张表会跟着训练一起被学出来。

### 2. one-hot 稀疏 vs embedding 稠密（关键直觉）

| 表示法 | 长这样 | 维度 | 问题 / 好处 |
|---|---|---|---|
| **one-hot** | `[0,0,1,0,...,0]` 只有 1 个 1 | =词表大小（5万+） | 又长又稀疏；任意两词"距离"全相等，毫无语义 |
| **embedding** | `[0.2,-0.7,0.4,...]` 全是小数 | 几百（300/768） | 稠密、可比较；语义直接体现在数值里 |

一句话：one-hot 是"身份证号"，能区分但不能比较；embedding 是"画像特征向量"，可以算"像不像"。后端类比——one-hot 像枚举 ID，embedding 像把对象哈希进同一个特征空间做相似检索（Day 21 RAG 就靠它）。

### 3. Word2Vec：CBOW 与 Skip-gram 直觉

怎么学出这张表？核心思想一句话：**"近朱者赤"——词由它的上下文定义**。"国王/女王"周围都是"宫殿、王位、统治"，向量自然会靠近。Word2Vec 给两种训练任务：

- **CBOW**（连续词袋）：用周围词猜中间词 —— 完形填空，"国王坐在 ___ 上"猜"王位"。**周围 → 中间**。
- **Skip-gram**：用中间词猜周围词 —— 给"国王"反推上下文。**中间 → 周围**，对低频词更准，最常用。

它就是 Day 1 那个小网络：输入词→隐藏层（这层权重就是 embedding）→softmax 猜词，反向传播一调，向量就排好了。

### 4. 余弦相似度 + 著名等式

比较两个向量像不像，看**夹角**而非长度，这就是余弦相似度：`cos = (A·B)/(|A||B|)`，1=同向、0=无关、-1=相反。语义关系藏在方向里，于是有了那个名场面：

```
vec(国王) - vec(男人) + vec(女人) ≈ vec(女王)
king        man        woman        queen
```

"减男人加女人"=减掉性别、保留王权，落点正好在女王附近。今天 practice.py 就手算验证它。

### 5. 语言模型 = 预测下一个词的概率分布

把上面连起来：**语言模型 = 给定前文，输出"下一个词"在全词表上的概率分布**。本质就是 Day 1 学的多分类（softmax over 5万词）。

```
"今天天气真" → P(好)=0.6, P(不错)=0.2, P(冷)=0.1, ... → 采样一个 → 接上 → 再猜 → ...
```

GPT 自始至终只做这一件事，温度/top_p（Day 11）就是调采样策略。词嵌入是它的"入口"，softmax 概率是它的"出口"。
