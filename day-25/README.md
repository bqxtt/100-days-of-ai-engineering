## 📖 学习内容（约 35 分钟）

### 1. 稠密向量检索（Dense Retrieval）：懂语义

把文档和查询各嵌成一个高维向量（今天用 `nomic-embed-text`，768 维），算**余弦相似度**取最近邻。向量是"语义指纹"——"宠物动物"能召回"猫/狗"，哪怕一个字都不重合。

```
向量 = embed("宠物动物");  相似度 = cosine(查询向量, 文档向量);  取 top-k
```

- **优**：懂同义/近义/跨语言，短查询也能召回相关文档；后端味=给一段文本建"语义索引"。
- **劣**：对**精确词**钝感——专有名词、缩写、订单号、罕见人名，向量分不出"BM25"和"RAG"谁更对；还吃嵌入模型质量、维度高、要近邻库（FAISS/HNSW）。

### 2. BM25 关键词检索（Keyword Retrieval）：抓精确词

BM25 是搜索引擎几十年的基石（ES 默认排序就是它），靠**词频 TF** + **逆文档频率 IDF** + **长度归一**打分：query 里的词在某文档出现得越多、且该词越稀有，分越高。

```
score = Σ_词  IDF(词) · TF·(k1+1) / (TF + k1·(1-b + b·doclen/avgdl))
```

- **优**：精确命中一字不差（缩写/ID/代码/人名）、可解释、无需模型、毫秒级、零样本。
- **劣**：**只认字面**——"番茄"查不到"西红柿"，完全不懂同义；问得越口语越抓瞎。

### 3. 混合检索 + RRF 融合（Hybrid Search）：互补取长

两路各跑一遍，再融合。问题是两边分数量纲不同（cosine 0~1 vs BM25 0~几十），硬加没意义。**RRF（Reciprocal Rank Fusion）**只看**名次**不看分数，天然跨量纲：

```
RRF(doc) = Σ_每一路  1 / (k + rank)      # k 常取 60；同时被两路靠前推的文档赢
```

- 一个文档若两路都排前面 → 两个大倒数相加 → 总分高，稳。某路偶发翻车，另一路兜底。
- 比"加权平均分数"更省心：无需调权重、无需归一化，对名次鲁棒——所以是工业界默认融合法。
- 进阶：融合后常再接 **rerank**（Day 26 讲）把 top-k 重排得更准。

### 4. 怎么选：一张表

| 维度 | 向量检索 | BM25 关键词 | Hybrid + RRF |
|---|---|---|---|
| 懂同义/语义 | ✅ 强 | ❌ 不懂 | ✅ |
| 精确词/缩写/ID | ❌ 弱 | ✅ 强 | ✅ |
| 要不要嵌入模型 | 要 | 不要 | 要 |
| 可解释性 | 低 | 高 | 中 |
| 成本/延迟 | 高（近邻库） | 极低（倒排） | 两路相加 |
| 默认建议 | 单独慎用 | 单独慎用 | **生产首选** |

一句话：**短查询/专有名词靠 BM25，口语/语义靠向量，不确定就 Hybrid 全都要、RRF 融。**
