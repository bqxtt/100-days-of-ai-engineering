## 📖 学习内容（约 25 分钟）

### 1. 为什么要量化：显存才是大模型的瓶颈

后端工程师对"内存换算"很熟。模型权重默认是 FP16（半精度，2 字节/参数）。一个 7B 模型光权重就要 `7e9 × 2 ≈ 14 GB`，刚好爆掉一张 16GB 显卡。推理时还要叠加 KV Cache（Day 8 的伏笔），显存更紧张。

量化就是把每个权重从 16-bit 降到 8-bit 甚至 4-bit：

| 精度 | 字节/参数 | 7B 模型权重 | 类比 |
|---|---|---|---|
| FP16 | 2 | ~14 GB | 无损 WAV |
| INT8 | 1 | ~7 GB | 高码率 MP3 |
| INT4 | 0.5 | ~3.5 GB | 低码率 MP3，能听 |

省的不只是显存：占用小→数据搬运少→带宽瓶颈缓解，很多场景**推理还更快**。结论：量化是把大模型塞进消费级显卡的头号手段。

### 2. FP16 / INT8 / INT4：从"小数刻度"到"整数刻度"

浮点数能表示很宽的范围且刻度细；整数只有有限个台阶（INT8 = 256 级，INT4 = 16 级）。量化做的事：把一段连续的浮点值，**映射到最近的整数台阶**，存整数；用的时候再乘回去（反量化）还原成近似浮点。差值就是量化误差，这就是"有损"的来源。

### 3. 对称 vs 非对称量化与 scale（今天的核心数学）

只需一个比例尺 `scale`：把浮点范围压进整数范围。

```
量化:   q = round(x / scale)        # 浮点→整数，存 q
反量化: x̂ = q × scale               # 整数→近似浮点，用 x̂
scale = max(|x|) / 127              # INT8 对称：127 个台阶
```

- **对称量化（symmetric）**：0 对齐 0，正负对称，只需 scale。实现简单、算得快，权重多用它。
- **非对称量化（asymmetric）**：再加一个 `zero_point` 平移，适合像 ReLU 后那种**只有正值**的分布，能省下"半个范围"不被浪费。

工程类比：scale 就是地图比例尺。比例尺定太大（范围太宽），细节糊；定太小，远处直接出图（溢出 clip）。**离群值（outlier）会撑大范围、稀释精度**——这正是 GPTQ/AWQ 要解决的痛点。

### 4. GPTQ / AWQ 的直觉：不是所有权重一样重要

最朴素的量化对所有权重一视同仁。但实测发现：**少数权重对输出影响巨大，砍坏它们精度暴跌**。两条思路：

- **GPTQ**：逐层量化，每量化一个权重就用二阶信息（Hessian）**补偿误差**，把损失摊给还没量化的邻居。像 code review 改一行就顺手修连带影响——4-bit 也几乎不掉点。
- **AWQ**（Activation-aware）：先看哪些通道激活值大=重要，给它们留更多精度（放大保护），其余照常压。"重要节点加固，其余压缩"——典型工程取舍。

两者都是 4-bit 主流方案；GPTQ 校准更重，AWQ 常更快更省。

### 5. 精度 vs 体积：天下没有免费量化

- **FP16→INT8**：体积减半，精度几乎无损，闭眼用。
- **INT8→INT4**：再砍一半，GPTQ/AWQ 加持下仅掉 1-2 分，性价比之王。
- **INT4 以下**：误差陡增，需特殊技巧，慎用。

记一句：**INT8 是免费午餐，INT4 是划算午餐，再低要付学费。**
