## 📖 学习内容（约 30 分钟）

### 0. 回顾：朴素 RAG 的天花板

Day 21-29 的标准 RAG 是一条直线：`query → 检索 top-k → 拼 prompt → 生成`。它有三个硬伤——
- **检索错了照样硬答**：召回不相关也塞进去，模型被带偏（幻觉）。
- **永远只检一次**：query 写得差、知识库没覆盖，没有第二次机会。
- **一刀切**：简单题（"1+1"）也走一整套检索，又慢又费。

今天的三种「高级 RAG（Advanced RAG）」就是各治一条：

| 方案 | 治的病 | 一句话 |
|---|---|---|
| **Self-RAG** 自我反思 | 检索错了硬答 | 模型自己发 token 决定：要不要检、检得好不好、答案有没有支撑 |
| **CRAG** 纠错检索 | 只检一次 | 给检索结果打分，差就改写 query 重检 |
| **Adaptive RAG** 自适应 | 一刀切 | 按问题难度路由：不检 / 检一次 / 多步迭代 |

### 1. Self-RAG：让模型当自己的裁判（自我反思检索）

朴素 RAG 总是检索。**Self-RAG（Self-Reflective RAG）**让模型生成几种特殊的「反思 token（reflection token）」来自评：
- `Retrieve?` —— **要不要检索**（简单题不检，省钱省时）
- `IsRel?` —— 召回这段**相关吗**（不相关就丢）
- `IsSup?` —— 我这句答案**被资料支撑吗**（没支撑 = 幻觉，重写）
- `IsUse?` —— 整体**有用吗**（打分挑最佳）

后端类比：每次外部调用都跟一个**健康检查**——不健康就别用它的返回。Self-RAG 把「检索 + 评分」编进生成本身。

### 2. CRAG：检索不够好就纠错重检（今天动手写它）

**CRAG（Corrective RAG，纠错式 RAG）** 在检索后加一个**轻量评估器（retrieval evaluator）**给召回文档打分，分三档：
- **correct（够好）**：直接用，精炼一下喂给生成。
- **incorrect（太差）**：丢掉本地结果，改写 query 去**网络搜索**重检。
- **ambiguous（拿不准）**：两者都来，混合用。

`practice.py` 写的就是 CRAG 最小骨架：**检索 → qwen2.5:3b 给每篇打 0~1 相关性分 → 最高分 < 阈值就改写 query 重检 → 过线再答**。把「网络搜索」简化成「改写后本地重检」，回路和真版一致。

### 3. Adaptive RAG：按难度路由，别拿大炮打蚊子

**Adaptive RAG** 先用一个分类器判**问题难度**，再路由：
- **简单**（"今天几号"）：**不检索**，模型直答。
- **中等**：**单次检索**就够。
- **复杂**（多跳推理）：**多步迭代检索**，边查边推。
这就是后端的**分级限流/分级缓存**：热点走快路，重活才上重型链路。省钱（少调嵌入/向量库）又提质（难题给足检索）。

### 4. 一句话串起来

**Self-RAG=自评要不要检/答得稳不稳，CRAG=检得差就纠错重检，Adaptive=按难度选路由。** 三者都在给朴素 RAG 装「反馈回路」——这正是从 Demo 走向生产的分水岭。

## 🤔 思考题（边做边想）

1. 评估器（LLM 当评委）也会打错分——给它过高阈值/过低阈值分别会怎样？这和你调告警阈值的权衡像不像？
2. CRAG 不限重检次数会怎样？该加什么护栏（最大轮数、预算上限）？和你给重试设上限一个道理。
3. Adaptive RAG 把简单题路由成「不检索」——省了成本，但路由分类器判错会怎样？召回率 vs 成本如何取舍？
4. Self-RAG 让模型自评「答案有没有被资料支撑」，能根治幻觉吗？哪些情况它仍可能自信地编？
